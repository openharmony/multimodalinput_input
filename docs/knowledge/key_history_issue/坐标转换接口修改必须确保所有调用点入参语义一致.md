# KP-002: 坐标转换接口修改必须确保所有调用点入参语义一致

## 严重级别
fatal

## 来源
多屏扩展场景主屏触屏无响应 + 窗口边缘光标样式异常（多单同根因链）

**问题详情**：

| 严重级别 | 现象 | 角色 |
|---------|------|------|
| 一般（Minor） | 扩展屏截屏选框跳变 | **初始触发问题**，修复此问题引入了后续3个严重问题 |
| 严重（Major） | 副屏鼠标点击后主屏触屏无响应，鼠标再次点击恢复 | 同根因衍生，必现 |
| 严重（Major） | 副屏在上/左时主屏触屏失效，**重启无法恢复**，需切换屏幕排列或断开扩展屏恢复 | 同根因衍生，必现，**影响最严重——用户设备触屏完全不可用** |
| 严重（Major） | 扩展屏窗口边框/四角光标无法触发形变缩放 | 同根因衍生，必现 |

**关键细节**：
- 初始问题（截屏跳变）定级仅"一般"，但为修复它而引入的3个问题全部为"严重"
- 最严重的问题恢复条件为"复杂的操作后恢复"（需切换屏幕排列或断开扩展屏），用户影响最大

## 问题回顾
多屏扩展场景，窗口下发的坐标计算矩阵新增缩放系数。修改 `TransformWindowCoord()` 接口统一按逻辑坐标进行计算后，部分调用点传入的仍是物理坐标（displayX + displayOffset），导致扩展屏在主屏上方/下方/左侧时 windowXY 计算错误，造成：
1. 主屏触屏点击无响应（计算的热区与实际窗口位置不一致）
2. 窗口边缘光标样式不切换（鼠标位置判断超出热区边界）

扩展屏在主屏右侧时恰好不触发问题（偏移量方向与坐标差抵消）。

## 代码陷阱模式

**陷阱：修改坐标转换函数的参数语义（如从"物理坐标"改为"逻辑坐标"），未逐一检查所有调用点是否已统一传参语义。**

此陷阱的隐蔽性在于：
1. 主场景（扩展屏在右侧）验证通过，误以为修改正确
2. 只有在特定方向（上/下/左）的扩展屏布局下才暴露
3. 坐标偏移量在不同方向上正负不同，导致某些方向恰好抵消错误

**衍生陷阱：修复低严重度问题引入高严重度问题。** 本案例中，初始问题（截屏选框跳变，Minor）的修复引入了3个严重问题（Major），且其中一个导致设备触屏完全不可用、重启无法恢复（需切换屏幕排列才能恢复）。这种"小修引入大问题"的模式在坐标/显示相关代码中尤其常见，因为这类代码的状态空间大（多屏多方向多旋转），验证难以穷举。

## 高风险代码区域

### 核心函数: TransformWindowCoord
- **定义**: `service/window_manager/src/*.cpp`
- **接口声明**: `service/window_manager/include/*.h`

```cpp
std::pair<double, double> WindowCoordinateManager::TransformWindowCoord(
    const WindowInfo &window, double logicX, double logicY) const
{
    UpdateDisplayOffset(window.displayId);
    double currX = logicX - current_display_offset_.first;   // 逻辑坐标 - 显示偏移
    double currY = logicY - current_display_offset_.second;
    Matrix3 transform(window.transform);
    if (window.transform.size() != MATRIX_SIZE || transform.IsIdentity()) {
        return {currX, currY};
    }
    Vector3 logicXY(currX, currY, 1.0);
    Vector3 windowXY = transform * logicXY;
    return { windowXY[0], windowXY[1] };
}
```

**参数语义**: `logicX`/`logicY` 必须是**逻辑坐标**（全局坐标），函数内部会减去显示偏移量。

### 关键风险调用点详解

**调用点7** — `service/event_dispatch/src/*.cpp`
```cpp
auto windowXY = COORD_MGR->TransformWindowCoord(*windowInfo,
    pointer_item.GetDisplayXPos() + display_info->x,
    pointer_item.GetDisplayYPos() + display_info->y);
```
- `GetDisplayXPos()` 返回物理显示坐标
- `display_info->x` 是显示偏移量
- 两者相加等于逻辑坐标，语义正确但表达隐晦
- **如果 TransformWindowCoord 参数语义变更，此处的表达式必须同步修改**

**调用点8** — `service/event_resample/src/*.cpp`
```cpp
// logicX 来自 coordX，赋值给 SetDisplayX/SetDisplayXPos，实际是显示坐标
auto logicX = it.second.coordX;
item.SetDisplayX(logicX);       // ← 证实 logicX 实际是显示坐标，非全局逻辑坐标
item.SetDisplayXPos(logicX);

// 显示坐标 + 显示偏移 = 全局逻辑坐标，当前语义正确
auto windowXY = COORD_MGR->TransformWindowCoord(window, logicX + display_info->x,
    logicY + display_info->y);
```
- 变量名 `logicX` 有误导性：实际是显示坐标，非全局逻辑坐标
- 当前传参语义正确（显示坐标+偏移=全局逻辑坐标），但如果 TransformWindowCoord 参数语义变更，此处的表达式极易被误改

## 坐标体系参考

输入服务中的坐标层次：
```
物理触摸坐标 (PhysicalCoordinate)
    ↓ 旋转校正 (RotateScreenCoords)
显示坐标 (display_x/y, 相对当前屏幕左上角)
    ↓ + 显示偏移 (DisplayInfo.x/y)
全局逻辑坐标 (GlobalCoords / logical_x/y)
    ↓ - 显示偏移 + 窗口变换矩阵
窗口坐标 (window_x/y, 相对窗口左上角)
```

关键数据结构：
- `DisplayInfo.x/y`: 扩展屏相对主屏的偏移，方向随旋转变化
- `DisplayInfo.direction`: DIRECTION0/90/180/270
- `DisplayMode`: FULL/MAIN/SUB/COORDINATION/GLOBAL_FULL等
- `DisplaySourceMode`: SCREEN_ALONE/EXPAND/MIRROR/EXTEND等
- `WindowEdgeArea`: 窗口边缘区域枚举

## 检查规则

修改坐标转换相关函数时，必须执行以下步骤：

### Step 1: 搜索所有调用点
```bash
grep -rn "TransformWindowCoord\|TransformDisplayCoord\|DisplayCoords2GlobalCoords\|UpdateTransformDisplayCoord" --include="*.cpp" --include="*.h"
```

### Step 2: 逐一确认每个调用点的入参语义
对每个调用点，回答：
1. 传入的 X/Y 坐标是物理坐标还是逻辑坐标？
2. 如果是表达式组合（如 `displayX + offset`），计算结果是否等价于函数要求的语义？
3. 在扩展屏位于主屏上/下/左/右四种布局下，该表达式是否始终正确？

### Step 3: 扩展屏场景矩阵验证
修改涉及扩展屏时，必须覆盖以下场景矩阵：

| 扩展屏位置 | 主屏操作 | 扩展屏操作 |
|-----------|---------|-----------|
| 右侧（默认） | 触屏/鼠标 | 触屏/鼠标 |
| 左侧 | 触屏/鼠标 | 触屏/鼠标 |
| 上方 | 触屏/鼠标 | 触屏/鼠标 |
| 下方 | 触屏/鼠标 | 触屏/鼠标 |

**每种位置下 displayInfo->x/y 的正负不同，是 bug 暴露的关键条件。**

### Step 4: 边缘场景
- 窗口跨屏（部分在主屏，部分在扩展屏）
- 扩展屏旋转（DIRECTION90/180/270）
- 折叠屏展开/折叠切换中坐标一致性

## 正确模式

```cpp
// 正确：调用点注释明确入参语义
auto windowXY = COORD_MGR->TransformWindowCoord(*windowInfo,
    pointer_item.GetDisplayXPos() + display_info->x,   // displayX + offset = logicalX
    pointer_item.GetDisplayYPos() + display_info->y);  // displayY + offset = logicalY
```

## 反面模式

```cpp
// 错误：函数参数语义从"物理坐标"改为"逻辑坐标"后，调用点未同步修改
auto windowXY = COORD_MGR->TransformWindowCoord(*windowInfo,
    pointer_item.GetDisplayXPos(),   // 仍然传入物理坐标，但函数已期望逻辑坐标
    pointer_item.GetDisplayYPos());  // 扩展屏非右侧时计算错误
```
