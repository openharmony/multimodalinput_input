# KP-003: 硬件传感器依赖必须识别产品差异

## 严重级别
major

## 来源
某移动产品 — 输入服务订阅距离传感器导致底电流劣化

**问题详情**：问题在某产品功耗测试中发现，当天回退，未流入正式发布版本。

## 问题回顾
输入服务侧为解决某产品口袋中按键误触问题，订阅了距离传感器，当传感器检测到遮挡时屏蔽特定快捷操作。但该产品实际由另一种高功耗传感器（而非标准低功耗器件）实现距离检测功能，该替代传感器功耗远大于标准器件。订阅行为导致高功耗传感器常开，整机功耗显著增加。

**关键细节**：代码调用的是标准的距离传感器类型ID，但底层硬件实现因产品不同而异——该产品的"距离检测"实际由高功耗传感器代理，而代码层对此完全无感知。

## 代码陷阱模式

**陷阱：代码通过统一传感器类型ID调用硬件，假设底层实现一致，未考虑不同产品的硬件代理差异可能带来副作用（功耗、精度、响应时间等）。**

此陷阱的隐蔽性在于：
1. 功能层面完全正确——距离检测功能正常工作
2. 副作用（功耗）不在功能测试范围内，需专门功耗测试才能发现
3. 产品硬件差异信息不在代码仓库中，开发人员通常不了解

## 高风险代码区域

### 1. 距离传感器订阅逻辑
- **文件**: `service/key_command/src/*.cpp`
- `RegisterDistanceSensor()` 仅对**折叠屏**注册距离传感器，非折叠屏直接跳过
- 当前逻辑是问题修复后的状态：原bug对所有产品统一订阅，某产品功耗暴增后回退为仅折叠屏使用

```cpp
void KeyCommandProcessor::RegisterDistanceSensor()
{
    if (sensor_registered_) {
        LOG_E("Has SubscribeSensor %{public}d", SENSOR_TYPE_ID_PROXIMITY);
        return;
    }
    if (!DeviceInfoHdr->IsFoldableDevice()) {  // 非折叠屏不注册距离传感器（修复功耗劣化问题）
        LOG_D("Device not foldable");
        return;
    }
    // 仅折叠屏走距离传感器订阅路径
    int32_t ret = SubscribeSensor(SENSOR_TYPE_ID_PROXIMITY, &user_data);
    // ... SetBatch, ActivateSensor ...
    sensor_registered_ = true;
}
```

**残留风险**：当前对折叠屏产品仍然无条件订阅距离传感器，未判断折叠屏内部是否也存在硬件差异（如不同折叠屏产品的传感器实现不同）。

### 2. 传感器SA就绪监听（仅日志，无实质初始化）
- **文件**: `service/module_loader/src/*.cpp`
- `AddSystemAbilityListener(SENSOR_SERVICE_ABILITY_ID)` 已注册
- 但 `OnAddSystemAbility` 回调中对 SENSOR_SERVICE_ABILITY_ID 仅打日志，无任何保护逻辑

### 3. 传感器回调
- **文件**: `service/key_command/src/*.cpp`
- `SensorDataCallback` 处理 `SENSOR_TYPE_ID_PROXIMITY` 事件
- 提取距离值，未考虑不同传感器的距离精度差异

### 4. 反注册逻辑
- **文件**: `service/key_command/src/*.cpp`
- `UnregisterDistanceSensor()` 调用 `DeactivateSensor` + `UnsubscribeSensor`
- 需确保在不需要时及时反注册以节省功耗

### 5. 其他硬件相关调用点（同类风险）
任何通过统一接口调用硬件的代码，都可能存在产品差异风险：
- 触屏设备枚举（不同触控芯片行为差异）
- 显示管理（折叠屏/直板屏/多屏扩展）
- 输入设备能力查询（不同设备支持的event类型不同）

## 检查规则

涉及硬件传感器/设备接口调用时，必须执行以下步骤：

### Step 1: 识别硬件依赖
在代码中搜索以下模式：
```bash
grep -rn "SubscribeSensor\|ActivateSensor\|SENSOR_TYPE_ID\|sensor_agent" --include="*.cpp" --include="*.h"
grep -rn "IsFoldableDevice\|DisplayMode\|DisplaySourceMode" --include="*.cpp" --include="*.h"
```

### Step 2: 评估产品差异影响
对每个硬件调用点，回答：
1. 不同产品对该硬件的实现是否有差异？（不同传感器型号、不同触控芯片、不同显示配置）
2. 硬件差异是否影响**非功能属性**（功耗、温度、延迟、精度）？
3. 代码中是否有产品规格判断来区分处理？

### Step 3: 增加产品规格保护
根据评估结果，在代码中增加保护：
1. **功耗敏感场景**：增加产品型号/硬件能力判断，对高功耗硬件走替代逻辑或限制使用
2. **能力不确定场景**：先查询硬件能力（如传感器是否支持），不支持时优雅降级
3. **生命周期管理**：确保硬件资源在不使用时及时释放（反注册/反激活）

### Step 4: 评估传感器常开的影响
订阅传感器后，传感器将常开直到反注册。需评估：
1. 传感器常开的功耗影响（查硬件规格书）
2. 是否可改为按需激活（如仅在屏幕亮起时激活，息屏时反注册）
3. 是否存在替代方案（如用系统事件替代传感器订阅）

## 正确模式

```cpp
// 正确：在订阅硬件前检查产品规格和硬件能力，不适用时走替代逻辑
void KeyCommandProcessor::RegisterDistanceSensor()
{
    if (sensor_registered_) {
        return;
    }
    // 当前逻辑：仅折叠屏使用距离传感器。如需扩展到更多产品，必须先评估硬件功耗差异
    if (!DeviceInfoHdr->IsFoldableDevice()) {
        LOG_D("Not foldable device, skip distance sensor");
        return;
    }
    // 扩展建议：即使折叠屏也应检查传感器功耗特性
    // 如果底层是高功耗代理（如某些产品），功耗过高，应走替代方案
    if (!IsSensorLowPower()) {
        LOG_D("Distance sensor is high-power, use alternative");
        UseAlternativePrevention();  // 走替代防误触路径
        return;
    }

    int32_t ret = SubscribeSensor(SENSOR_TYPE_ID_PROXIMITY, &user_data);
    // ...
}

// 正确：按需激活，息屏时反注册节省功耗
void KeyCommandProcessor::OnScreenOff()
{
    UnregisterDistanceSensor();  // 息屏不需要距离检测，释放硬件资源
}

void KeyCommandProcessor::OnScreenOn()
{
    RegisterDistanceSensor();    // 亮屏时按需注册
}
```

## 反面模式

```cpp
// 错误：无条件订阅传感器，不考虑产品差异和功耗影响
int32_t KeyCommandProcessor::RegisterDistanceSensor()
{
    // 直接订阅，不判断产品硬件实现
    SubscribeSensor(SENSOR_TYPE_ID_PROXIMITY, &user_data);
    SetBatch(SENSOR_TYPE_ID_PROXIMITY, &user_data, ...);
    ActivateSensor(SENSOR_TYPE_ID_PROXIMITY, &user_data);
    // 传感器从此常开，高功耗代理传感器导致功耗显著劣化
}
```
